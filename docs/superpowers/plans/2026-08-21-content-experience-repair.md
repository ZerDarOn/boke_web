# INK.SPIRIT 内容模块修复与体验升级方案

> 状态：待评审，不执行代码修改  
> 生成日期：2026-08-21  
> 范围：游戏、追番、音乐馆、日记、相册、文章与 Markdown 导入  
> 技术栈：React 19 + TypeScript + Vite + Tailwind CSS 3 + Express + Prisma + PostgreSQL

## 1. 目标

把现有的“外部资料列表”升级为真正属于站长的个人文化档案馆，同时先消除数据录入、导入、分页和展示链路中的确定性错误。

本方案追求四个结果：

1. 数据完整：数据库中已有内容可以被完整查询、筛选和展示。
2. 录入顺畅：同步或导入后可以批量整理，不必逐条填写大量基础资料。
3. 内容有主见：详情页优先呈现“我的点评、经历和策展”，外部简介退居辅助位置。
4. 阅读舒适：文章、日记和媒体详情在桌面端与移动端都有合理的内容宽度和导航方式。

## 2. 非目标

本轮规划不包含：

- 更换 React、Express、Prisma 或数据库。
- 将所有内容迁移为纯 Markdown 文件运行。
- 抓取或绕过受版权保护的付费音视频资源。
- 在未确认平台授权条件前实现网易云完整账户登录同步。
- 一次性重写全部页面或替换现有赛博水墨视觉语言。

## 4. 产品原则

### 4.1 外部资料与个人内容分层

每个游戏或动漫详情分为两类内容：

- 资料层：名称、封面、制作方、类型、发行日期、外部简介、平台链接。
- 个人层：一句话结论、评分、长评、游玩/追番日志、精彩片段、截图、标签和关联文章。

前台默认先展示个人层；资料层作为侧栏、折叠区或页面下半部分。

### 4.2 导入不等于发布

Steam、追番数据或 Markdown 导入后先进入“待整理”状态。管理员应能批量：

- 选择公开或隐藏。
- 设定状态、标签和分类。
- 查看缺失字段。
- 预览最终效果。
- 分批发布。

### 4.3 服务端负责完整分页

所有列表统一使用服务端分页和元数据：

```text
data: [...]
meta: { total, page, limit, hasMore }
```

前端不得先截取默认 10 条再做“伪分页”，也不得用有限列表推导完整相册、平台或标签集合。

### 4.4 内容可降级

- 视频不可播放时仍显示封面、标题、说明和外链。
- 音乐第三方接口失效时仍显示最近一次歌单快照。
- 图片或封面失效时使用真实的缺图状态，不显示虚构设备参数。
- 富内容为空时展示明确的空状态，不保留大块空卡片。

## 5. 模块边界与建设顺序

### 5.1 模块边界

1. **内容契约与导入模块**：负责 Markdown 解析、字段映射、预览、冲突处理和导入报告。
2. **游戏与追番档案模块**：负责外部元数据、个人点评、日志、精彩片段和关联内容。
3. **音乐策展模块**：负责音乐源、歌单快照、排序置顶、分组、搜索和个人精选。
4. **日记与相册模块**：负责生活记录、相册分页、批量照片管理和真实评论。
5. **文章阅读模块**：负责 Markdown 渲染、正文排版、目录和跨设备阅读体验。
6. **后台整理工作台**：负责同步后批量整理、缺失字段提示、发布状态和操作反馈。

### 5.2 建设顺序

```text
正确性基线
  → 统一分页与导入契约
    → 数据模型扩展与迁移
      → 后台录入/整理能力
        → 前台详情与搜索体验
          → 回填、灰度发布与复盘
```

正确性修复必须先完成，否则新增的富内容仍可能因分页、字段映射或渲染错误无法显示。

## 6. 关键架构决策

### ADR-01：外部元数据与个人内容分开维护

- **Decision**：游戏和动漫保留现有主表存放基础资料，个人日志、精彩片段和分集/游玩记录使用具备外键的领域子表。
- **Context**：现有 `notes` 字段无法承载有顺序、有类型、可剧透、可关联媒体的内容。
- **Options**：继续增加主表字符串字段；存入一个大 JSON；建立领域子表。
- **Chosen**：主表保留摘要字段，复杂内容使用 `GameJournal`、`GameHighlight`、`AnimeEpisodeNote`、`AnimeHighlight` 等领域子表。
- **Tradeoff**：迁移和接口数量增加，但可验证、可排序、可分页，避免无类型 JSON 长期失控。
- **Rollback**：子表功能可通过功能开关停用，主表现有字段和页面继续工作。

### ADR-02：列表统一为服务端分页

- **Decision**：游戏、追番、相册照片、日记和音乐曲目统一消费服务端分页元数据。
- **Context**：当前默认 10 条、固定 100 条和客户端二次切片导致内容显示不全。
- **Options**：提高固定上限；一次加载全部；服务端分页/游标。
- **Chosen**：后台表格使用页码分页，前台媒体流使用分页或“加载更多”；筛选条件全部进入服务端查询。
- **Tradeoff**：前端状态管理略增，但规模增长后行为稳定。
- **Rollback**：保留原列表接口参数兼容，旧页面可继续请求第一页。

### ADR-03：音乐采用“来源 + 快照 + 策展”三层模型

- **Decision**：不把第三方 Meting 的实时返回当作唯一数据源。
- **Context**：版权、限流或第三方服务失效会让整个音乐馆变空。
- **Options**：继续实时代理；完整镜像音频；缓存元数据并实时请求播放地址。
- **Chosen**：保存音乐来源和曲目元数据快照；播放时再获取可用地址；个人置顶、标签、备注独立保存。
- **Tradeoff**：曲目信息可能短暂过期，但页面可浏览、可搜索且不依赖单次外部请求。
- **Rollback**：关闭快照读取后可回退现有 APlayer + Meting 实时模式。

### ADR-04：Markdown 继续以数据库正文为运行时事实源

- **Decision**：保留 `Post.content` 中的 Markdown 字符串，重写导入映射与预览，不切换为运行时文件读取。
- **Context**：现有权限、搜索、API、编辑器和文章关联都依赖数据库记录。
- **Options**：纯文件；纯数据库富文本；数据库保存 Markdown。
- **Chosen**：数据库保存 Markdown；导入器采用每种内容类型独立、强类型的映射器。
- **Tradeoff**：文件不是实时事实源，但部署和权限模型保持稳定。
- **Rollback**：导入器可单独回滚，不影响已保存正文。

### ADR-05：目录使用渐进披露

- **Decision**：桌面目录默认为窄轨或浮层，移动端使用悬浮按钮 + 底部面板。
- **Context**：固定 256px 目录挤压正文，移动端目录先于正文造成长距离滚动。
- **Options**：永久侧栏；正文顶部目录；渐进披露。
- **Chosen**：大屏窄轨展开，小屏底部面板；目录只观察文章正文容器内标题。
- **Tradeoff**：目录少一次直接可见，但正文获得稳定阅读宽度。
- **Rollback**：保留现有目录组件，可通过功能开关恢复展开侧栏。

## 7. 领域风险

### 7.1 Invariants

- 同一 Steam 游戏必须由 `(platform, platformId)` 唯一识别，重复同步不能生成重复记录。
- 同步不得覆盖个人评分、点评、标签、公开状态和手工封面。
- 相册 `photoCount` 必须与实际照片数量一致，删除相册不能误删照片。
- 导入覆盖必须保留记录身份或在事务中完成替换，不能先删旧内容后因新内容失败而丢失。
- 私密日记、隐藏游戏和草稿内容不得出现在公共接口、搜索或推荐中。

### 7.2 Atomicity

- Markdown 覆盖导入必须在单个数据库事务中完成。
- 音乐源刷新采用“生成新快照 → 验证 → 激活”，失败时保留上一版快照。
- 批量公开、移动相册、批量打标签需要返回逐项结果，不得静默半成功。
- Schema 迁移和数据回填分离，先添加兼容字段，再回填，最后切换读取。

### 7.3 Concurrency

- Steam 手动同步与定时同步需要互斥锁或幂等作业 ID。
- 同一音乐源重复刷新要合并，旧请求不得覆盖新快照。
- 后台编辑使用 `updatedAt` 做乐观并发检查，避免两个页面互相覆盖。

### 7.4 Side effects

- 上传后未保存的图片或视频会形成孤儿文件，需要草稿资源标记和定期清理。
- 外部同步、音乐刷新和批量导入要记录作业状态与失败项。
- 删除有媒体附件的内容时先软删除记录，附件延迟清理，提供恢复窗口。

### 7.5 Trust boundaries

- 所有后台写操作继续强制 `authenticate + requireAdmin`。
- 外部 URL 必须限制协议并防止服务端请求伪造；视频嵌入采用允许域白名单。
- Markdown 导入限制文件大小、ZIP 解压路径和文件数量，禁止路径穿越。
- 评论接口需要限流、长度限制和服务端清洗。

### 7.6 Observability

- 每次同步/导入记录作业 ID、来源、总数、创建、更新、跳过、失败和耗时。
- 前端错误状态展示可操作原因，不只显示“加载失败”。
- 关键指标：列表返回总数、快照年龄、第三方音乐失败率、导入字段校验失败分布。

### 7.7 Performance

- 列表只返回卡片所需摘要，长评、日志和评论在详情接口加载。
- 图片生成响应式缩略图，视频默认不自动加载。
- 关联内容避免逐项查询，采用批量查询或关系 include。
- 曲目搜索使用数据库索引，不在浏览器中扫描无限列表。

## 8. 分阶段微计划

### Phase 0：基线与保护

#### Task 0.1｜建立回归清单与数据备份

- **Input**：当前 PostgreSQL 数据、上传目录、现有 API 行为。
- **Output**：数据库备份、关键数量快照、公开/私密样本清单。
- **Risk**：迁移或回填误改已有内容。
- **Rollback**：恢复数据库备份与上传目录快照。
- **Flag**：涉及持久化副作用，实施前必须确认备份可恢复。

#### Task 0.2｜为已确认错误补失败测试

- **Input**：C-01 至 C-10。
- **Output**：枚举、分页、导入映射、截图、相册评论和权限回归测试。
- **Risk**：修复后再次回归。
- **Rollback**：纯测试任务，无运行时副作用。

### Phase 1：正确性与完整显示

#### Task 1.1｜统一游戏枚举契约

- **Input**：Prisma `GamePlatform`、`GameStatus` 与后台显示文案。
- **Output**：共享枚举值、显示标签适配器、旧异常值审计脚本。
- **Risk**：手动录入失败、筛选遗漏。
- **Rollback**：保留只读兼容映射，异常数据可恢复原值。

#### Task 1.2｜修复追番、游戏和日记分页参数

- **Input**：现有列表 API 与 React Query hooks。
- **Output**：完整传递 `page/limit/filter`，页面消费 `meta`。
- **Risk**：当前 138 部追番只展示 10 部、未来游戏超过 100 条被截断。
- **Rollback**：接口保留默认第一页行为。

#### Task 1.3｜重建相册查询链路

- **Input**：现有 `/gallery/albums` 和照片列表接口。
- **Output**：相册首页直接查询 Album；详情使用服务端分页；空相册可见。
- **Risk**：相册缺失、最多显示 10 张。
- **Rollback**：保留旧派生 hook 一版但不作为默认路径。

#### Task 1.4｜修复截图与真实评论

- **Input**：游戏截图 URL、照片评论后端接口。
- **Output**：真实 `<img>`/灯箱展示；评论提交、失败提示和缓存刷新。
- **Risk**：媒体不可见、评论刷新消失。
- **Rollback**：关闭评论输入或截图灯箱，不影响主体详情。

#### Task 1.5｜重写强类型 Markdown 映射器

- **Input**：Front Matter、各 Prisma 模型字段。
- **Output**：Post/Project/Anime/Diary/Gallery 独立映射器、dry-run 预览、逐字段校验报告。
- **Risk**：未知字段、`published/isPublished`、`readTime/readingTime` 等错配。
- **Rollback**：旧导入入口保持关闭，已导入内容不回写。
- **Flag**：覆盖导入必须使用事务，禁止“先删后写”。

### Phase 2：数据模型与后台录入

#### Task 2.1｜扩展游戏个人档案

- **Input**：现有 Game、notes、screenshots 和关联 ID。
- **Output**：一句话结论、Markdown 长评、维度评分、游玩日志、精彩片段、截图说明、关联内容选择器。
- **Risk**：主表继续膨胀或复杂内容无法排序。
- **Rollback**：新字段和子表均可选，旧详情继续读取原字段。

#### Task 2.2｜扩展追番个人档案

- **Input**：现有 Anime、synopsis、notes、进度。
- **Output**：短评、长评、剧透区、单集笔记、角色/配乐记录、精彩片段。
- **Risk**：外部简介继续掩盖个人内容。
- **Rollback**：关闭富内容区后保留当前资料页。

#### Task 2.3｜建立同步后整理工作台

- **Input**：Steam 同步结果、追番导入结果。
- **Output**：缺失字段筛选、批量公开/隐藏、状态、标签、封面和发布预览。
- **Risk**：同步数据大量堆积但无法转化为内容。
- **Rollback**：工作台独立路由，不替换原 CRUD 表格。

#### Task 2.4｜音乐来源与策展模型

- **Input**：`music_sources` SiteConfig JSON 与默认歌单。
- **Output**：MusicSource、TrackSnapshot、Curation 数据结构；排序、置顶、分组、标签、点评。
- **Risk**：第三方服务故障、重复曲目、排序丢失。
- **Rollback**：保留 SiteConfig 读取适配器，可退回原播放器。

#### Task 2.5｜统一长短日记编辑器

- **Input**：Diary 的 `content/longContent`、两个后台入口。
- **Output**：统一编辑器、类型切换、草稿/可见性、封面、附件、Markdown 预览。
- **Risk**：长正文读取字段不一致。
- **Rollback**：先双写 `content` 与旧字段，确认后再停止旧字段写入。

#### Task 2.6｜完善相册批量管理

- **Input**：Album、GalleryImage、上传服务。
- **Output**：批量上传、EXIF 提取、批量标签/地点/日期、排序和封面选择。
- **Risk**：大量文件上传中断、元数据误覆盖。
- **Rollback**：每张照片独立结果；失败项可重试，不回滚成功项。

### Phase 3：前台内容体验

#### Task 3.1｜重构游戏详情

- **Input**：基础资料、个人档案、媒体和关联内容。
- **Output**：“我的结论 → 点评 → 高光/截图 → 游玩日志 → 基础资料”的叙事结构。
- **Risk**：无富内容时页面再次出现大块空白。
- **Rollback**：按区块特性开关回退当前详情。

#### Task 3.2｜重构追番详情

- **Input**：个人点评、分集笔记、名场面、外部简介。
- **Output**：个人内容优先、剧透保护、进度和评分变化可视化。
- **Risk**：剧透内容误公开。
- **Rollback**：默认折叠全部剧透块。

#### Task 3.3｜升级音乐馆

- **Input**：音乐源、曲目快照和个人策展。
- **Output**：歌单分组、搜索、筛选、默认/置顶、不可播放标记和个人点评。
- **Risk**：第三方播放地址失效。
- **Rollback**：播放失败时降级为元数据浏览和原平台跳转。

#### Task 3.4｜升级文章排版与目录

- **Input**：现有 MarkdownRenderer、TableOfContents、PostDetail。
- **Output**：720–780px 正文、出版物式层级、桌面窄轨目录、移动端底部目录、正文范围内标题追踪。
- **Risk**：代码块、表格和大图被正文宽度裁切。
- **Rollback**：保留旧样式类和目录模式开关。

#### Task 3.5｜升级相册与日记浏览

- **Input**：真实分页相册、统一日记正文。
- **Output**：相册灯箱前后切换、筛选；日记时间轴、标签和年份视图。
- **Risk**：大图加载和移动端内存压力。
- **Rollback**：关闭预加载和复杂过渡，保留基础网格。

### Phase 4：迁移、发布与复盘

#### Task 4.1｜数据回填

- **Input**：88 个游戏、138 部动漫、旧音乐配置和现有 Markdown。
- **Output**：异常枚举修正、富内容默认值、音乐源迁移、导入兼容报告。
- **Risk**：历史手工字段被覆盖。
- **Rollback**：回填前快照 + 可逆迁移脚本。

#### Task 4.2｜灰度发布

- **Input**：新旧页面与功能开关。
- **Output**：先管理员预览，再公开新列表，最后切换详情。
- **Risk**：新接口在真实数据量下出现遗漏。
- **Rollback**：逐模块关闭功能开关，不做全站回滚。

#### Task 4.3｜内容运营首批回填

- **Input**：站长选择的游戏、动漫、歌单、日记和相册。
- **Output**：游戏/动漫各 3–5 个完整样板，2–3 个策展歌单，1 篇长日记，1 个真实相册。
- **Risk**：功能完成但页面仍因没有内容显得空洞。
- **Rollback**：内容保持草稿，不影响功能发布。

## 9. 测试策略

### 9.1 后端

- 枚举和请求 schema 边界测试。
- 分页第一页、末页、空页、筛选组合测试。
- Steam 重复同步幂等测试。
- Markdown 每种内容类型的合法、缺字段、未知字段、覆盖事务测试。
- 相册评论鉴权、限流、清洗测试。
- 私密/隐藏内容不出现在公共列表和详情的测试。

### 9.2 前端

- 使用 Testing Library 按角色和标签查询关键表单。
- 管理后台批量整理、失败重试和未保存离开提醒。
- 列表加载、空、错误、无更多数据状态。
- 视频、音乐、图片加载失败降级状态。
- 文章目录键盘操作、焦点管理和移动端面板。

### 9.3 端到端

- Steam 同步 → 待整理 → 批量公开 → 前台可见。
- 追番导入 138 条 → 分页浏览 → 搜索定位 → 打开详情。
- Markdown dry-run → 导入 → 正文、目录、图片和代码块一致。
- 创建相册 → 批量上传 20 张 → 翻页 → 评论 → 刷新后仍存在。
- 添加多个音乐源 → 排序置顶 → 搜索曲目 → 第三方故障降级。

## 10. 验收标准

### P0 正确性门槛

- 138 部追番可以全部分页访问，前后台总数一致。
- 游戏平台和状态录入不再产生非法枚举值。
- 超过 100 个游戏后仍能完整查询和管理。
- 任意相册可见，超过 10 张照片后分页正常。
- 游戏截图真实显示，照片评论刷新后仍存在。
- 所有支持的 Markdown 类型均有成功导入样例；未知字段在预览中明确报告。

### P1 内容能力门槛

- 游戏和动漫都能录入短评、长评、至少一种日志与精彩片段。
- 富内容为空时页面保持紧凑，不显示无意义空容器。
- 音乐源支持拖拽排序、默认、置顶、分组和搜索。
- 长短日记通过同一后台入口管理，正文读写字段一致。

### P2 体验门槛

- 文章正文在 1440px 屏幕上行宽不超过约 780px。
- 桌面目录折叠后不明显挤压正文；移动端目录不位于正文之前。
- 375px、768px、1024px、1440px 无横向滚动和遮挡。
- 键盘可操作所有筛选、目录、灯箱和后台主要表单。

## 11. 发布策略

1. Phase 1 使用小步补丁发布，不改数据库结构的任务优先。
2. Phase 2 采用“新增字段/表 → 双写 → 回填 → 切读 → 停旧写”的兼容迁移。
3. 每个前台新详情页使用独立功能开关。
4. 先选择少量完整内容做管理员预览，再逐模块公开。
5. 每个阶段保留独立回滚点，不把六个模块绑成一次大发布。

## 12. 工作量与并行建议

| 阶段 | 复杂度 | 可并行内容 |
|---|---|---|
| Phase 0 | S | 测试清单、数据备份 |
| Phase 1 | M–L | 游戏枚举、追番分页、相册链路、导入映射可分组并行 |
| Phase 2 | L | 游戏/追番、音乐、日记/相册三条领域线可并行；迁移统一审查 |
| Phase 3 | L | 各前台页面可并行，设计系统和交互规范需共享 |
| Phase 4 | M | 回填、E2E、内容样板可部分并行 |

预计应拆成 4–6 个可独立验收的开发批次，不建议一次完成全部模块。

## 13. 建议的第一批实施范围

第一批只处理正确性，不新增富内容模型：

1. 游戏枚举契约。
2. 追番分页参数和完整显示。
3. 相册真实相册接口与照片分页。
4. 游戏截图和相册真实评论。
5. Markdown 强类型导入映射与 dry-run。
6. 对以上行为补回归测试。

第一批完成后，再以 3–5 个游戏和动漫样本评审富内容详情设计，确认方向后进入 Phase 2。
